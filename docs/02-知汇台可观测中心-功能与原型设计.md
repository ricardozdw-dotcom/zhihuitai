# 知汇台 · 可观测中心功能与原型设计

状态：待用户审阅；本轮为功能设计，尚未修改前端页面或后端。

## 1. 设计目标与现状

围绕四个问题设计：知识为什么没有成功入库？Agent 为什么失败或卡住？这轮回答用了什么依据？成本花在了哪里？

现有 `frontend/src/pages/LogsPage.tsx` 提供对话日志、模型调用、Token/耗时和导入任务，并通过固定阶段生成对话链路示意。现有数据结构不足以表达真实的节点嵌套、并发、重试、Skill 生命周期和供应商费用。问答应用中 Agent 场景仍是待开放状态，因此新增 Agent 数据先以明确标记的演示记录呈现。

本方案建议保留“知汇台”的整体视觉，把现有“日志中心”升级为“可观测中心”。复用现有入口，避免同时出现两个用途重叠的日志模块。页面设计不依赖先选定某家观测平台。

## 2. 页面结构

| 页面 | 首要任务 | 核心内容 |
| --- | --- | --- |
| 总览 | 发现异常和成本变化 | 运行量、错误率、P50/P95、Token、费用趋势、最近异常、数据完整度 |
| 知识库构建 | 定位某批文件在哪一步失败 | 批次→文件→处理阶段；队列、OCR、分块、索引、发布版本 |
| Agent 运行 | 还原一次任务的完整执行 | 运行列表、执行树、时间瀑布、逐次模型/工具/Skill/上下文详情 |
| 对话日志 | 检查用户实际看到的问答 | 会话→轮次→请求链路、引用、检索证据、反馈 |
| 用量与费用 | 解释资源与费用归因 | 按应用/知识库/模型/供应商汇总，调用级明细和定价依据 |
| 异常中心 | 集中处置重复问题 | 错误聚合、影响范围、异常事件、关联运行、处理状态 |

模型调用从原有独立页签整合到统一运行节点和费用明细中；保留“仅看模型调用”快捷筛选。观测设置放在右上角，包括保留期、采集模式、定价与告警规则。

原型路由建议：`/#/observability/overview`、`builds`、`agents`、`conversations`、`usage`、`exceptions`。原有 `/#/logs` 跳转到总览；详情使用独立路由以支持复制链接和返回后保留筛选。

## 3. 统一信息与交互

- 顶部共享时间范围（默认最近 24 小时）、环境、应用、知识库、供应商和运行状态筛选；只展示当前页适用的筛选项。
- 搜索支持运行 ID、Trace ID、会话 ID、任务 ID、文件名；正文搜索独立开启并遵循内容采集范围。
- 时间采用当前界面时区并显示时区；耗时统一由开始/结束时间计算。
- 列表支持排序、分页、筛选重置；详情返回保留列表位置和筛选。
- 运行中的数据可选自动刷新；展示数据更新时间，翻看历史记录时不跳动。
- 全局筛选跨页保留；下钻对象作为附加筛选，不默默覆盖时间范围。
- 没有数据、未接入、内容未采集、采集延迟、采样、已脱敏、内容截断和数据已过期分别显示，不能统一用空白表示。
- 原型顶部标记“演示数据”；演示费用不与真实数据混合汇总。

状态与质量分开：运行状态包含排队、运行中、等待人工、成功、部分成功、失败、超时、已取消、未知。成功只代表执行完成，不代表回答正确；拒答、空召回和用户差评属于独立业务结果。

## 4. 知识库构建观测

### 4.1 批次与文件列表

批次展示知识库、导入来源、文件数量、创建时间、排队时间、运行耗时、完成/失败/跳过数量、当前阶段、预计/实际成本和索引版本。展开后查看单文件状态、格式、大小、页数、处理阶段、分块数量、错误摘要。

批次状态允许“部分成功”；已完成文件仍可检索，失败文件能独立定位。上传已完成不等于知识已可检索，文件需要显示“索引已写入”和“已发布可检索”两个不同节点。

### 4.2 构建详情

按实际执行情况显示以下阶段；未执行阶段标记跳过及原因：

1. 上传与校验：文件类型、内容哈希、重复文件、加密/损坏、大小限制。
2. 排队与任务分发：队列、worker、等待时长、心跳、尝试次数。
3. 解析与 OCR：解析器/版本、总页数、原生文本页、OCR 页、失败页、云服务请求 ID。
4. 标准化：换行/噪声清理、标题结构、表格与图片文字保留、解析警告。
5. 分块：九种分块策略、参数快照、父子关联、实际分块数、空块/超长块统计、分块预览。
6. 索引增强：标题、关键词、问题、摘要；各项生成状态、Token 和耗时。
7. Embedding：模型、维度、批量大小、批次数、Token、失败与重试。
8. 写入与发布：已写入/目标数量、向量维度错误、索引版本、发布时间、可检索状态。

每个阶段展示输入/输出摘要、耗时、错误、警告和相关调用明细。不能把向量写入成功自动当作检索质量通过；质量测试结果单独关联。

进度优先使用已完成文件、页数、批次数等可量化单位。无法计算总量时展示当前阶段和已处理数量，不编造精确百分比或完成时间。

构建页可以跳转文档及其后置元数据编辑；元数据不重新成为导入步骤。

## 5. Agent 运行观测（核心）

### 5.1 运行列表

列：开始时间、Agent/版本、输入摘要、输出摘要、状态、当前节点、运行轮数、工具次数、Skill 次数、Token、费用、耗时、异常标签。

筛选：Agent、应用版本、模型、工具、Skill、状态、异常类别、耗时区间、Token/费用区间、Trace ID、会话。快捷条件：失败、长时间运行、超预算、工具失败后恢复、上下文溢出、等待人工。

根运行同时展示最终结果与过程警告。例如工具首次失败后重试成功，根运行可以成功，但必须保留“经历 1 次重试”的警告。

### 5.2 运行详情布局

详情顶部：任务输入摘要、状态、输出摘要、开始/结束时间、总耗时、聚合 Token、费用及来源、关联会话、Agent/Prompt/Harness 配置版本。

主体采用“左侧执行树 + 中间时间瀑布 + 右侧节点检查器”；窄屏保留执行树和检查器，瀑布可切换查看。大详情占满内容区，不挤在现有 560px 抽屉内。

左侧定位父子、子 Agent、循环轮次、重试、并行分支；瀑布定位等待、执行与首 Token 延迟。点击异常可定位节点，支持只看错误、模型、工具、Skill 或检索。

节点详情页签：概览、输入输出、上下文、用量费用、事件与异常、原始结构化记录。输入输出支持格式化/原文切换、搜索、折叠长内容、复制已展示的脱敏内容。

### 5.3 节点类型与记录内容

| 类型 | 需要观测的内容 |
| --- | --- |
| Agent / 子 Agent | 输入任务、最终输出、当前步骤、结束原因、父子关系、轮数、配置版本 |
| LLM | 实际发送的消息、模型/供应商、参数、输出、finish reason、工具调用请求、首 Token、流式结束情况、usage |
| Tool / MCP Tool | 名称和版本、参数、返回、调用 ID、执行状态、排队/执行时长、超时、重试、错误、外部请求 ID |
| Skill | 名称、来源、版本/哈希、触发依据（运行时有记录时）、加载结果、指令引用、执行片段、关联工具/模型、完成依据 |
| Retrieval / Rerank | 原始/改写问题、过滤条件、检索配置、候选分块、得分及分数类型、重排顺序、最终送入上下文的片段 |
| Context / Memory | 系统配置、历史消息、检索证据、工具返回、记忆读写、压缩/裁剪前后摘要与 Token |
| Harness | 调度、预算检查、审批、checkpoint、恢复、取消、重试、资源限制与事件 |

这里的 Harness 指承载 Agent 的执行环境与控制机制，包括调度、工具执行、上下文管理、预算、审批和恢复。

Skill 是指令与流程资源，不一定是单个可执行函数。原型必须区分“已发现 / 已加载 / 执行中 / 已完成 / 失败 / 跳过”，并记录生命周期事件。加载成功不能自动推导执行成功。如果底层运行时只提供加载事件，就显示“已加载，执行完成情况未提供”。

工具或 Skill 本身没有直接模型调用时，直接 Token 显示“不适用”；其子节点产生的 Token 作为“关联模型用量”展示，不虚构独立消耗。

### 5.4 调用上下文

按每一次模型请求展示真正发送的上下文快照，而非只显示会话最初的用户问题：

- 系统/开发者配置及 Prompt 版本、当前输入、历史消息。
- 本轮检索引用的分块与索引版本、工具返回、加载的 Skill 指令。
- 工具定义、记忆、附件引用及运行时实际提供的其他信息。
- 上下文上限、已用 Token、预留输出、各部分 Token 占比。
- 截断/摘要/压缩事件；仅有估算时标记“估算”。

支持比较相邻两次模型请求的上下文增删，定位重复历史、过长工具返回和丢失的证据。内容只有在被采集时才可展示；不补写模型内部思维链，不把模型可见输出之外的推断当成日志。

### 5.5 Harness 异常与关联

| 分类 | 典型事件 | 详情需回答的问题 |
| --- | --- | --- |
| 模型/供应商 | 超时、限流、鉴权、流中断、内容拦截、usage 缺失 | 哪次请求、何时失败、是否重试/切换供应商、费用是否已知 |
| 工具 | 未注册、参数 schema 错误、执行超时、返回格式错误 | 参数是什么、是否实际执行、是否已有外部副作用、失败返回是什么 |
| Skill | 找不到、版本不一致、加载失败、执行缺少依赖 | 哪个版本、哪个环节、是否进入执行、关联了哪些调用 |
| 上下文 | 超窗口、工具返回过大、裁剪丢失关键信息 | 哪部分增长、裁剪发生在何时、后续请求使用了什么 |
| 编排 | 达到最大轮数、疑似循环、子任务失败、任务无心跳 | 哪个分支卡住、最后事件、终止原因、恢复点是否有效 |
| 运行环境 | 网络、沙箱、文件路径、进程退出、内存/资源不足 | 执行环境、退出码、可定位的错误摘要 |
| 控制与恢复 | 等待审批、拒绝审批、取消、预算耗尽、checkpoint 失败 | 等待还是失败、由谁触发（若有身份）、恢复是否产生新尝试 |
| 观测自身 | 事件丢失、父节点缺失、上报延迟、usage 未采集 | 链路是否完整、哪些数据未知、是否影响统计 |

异常同时保存机器错误码、可读说明、发生节点、时间、attempt、可重试性、最终结果。原因未经确认时显示“疑似原因”，不能用模型推断替代原始证据。

只有监测到心跳缺失时，状态先变“未知/疑似失联”，由执行器终态确认超时或失败。不得因为日志停止就直接判定任务成功或失败。

## 6. 对话日志

保留现有对话入口并增加会话与轮次两层：

- 会话列表：标题、来源应用、轮数、最近活动、总 Token/费用、业务结果与反馈。
- 轮次列表：用户问题、最终回答摘要、首 Token、端到端耗时、引用数量、运行状态。
- 轮次详情：完整输入输出、历史消息、召回/重排/引用、模型调用、关联 Agent 运行。
- 检索证据：命中文档、分块内容、位置、知识库/索引版本、检索与重排分数；不同分数类型分别标记。
- 区分空召回、依据不足拒答、引用缺失、请求失败、用户取消和正常回答。
- 反馈：有用/无用、原因、人工处理标记；反馈不自动生成质量评分。

从对话跳到 Agent 运行再到某次工具或模型调用，始终保持会话和 Trace 关联。一个请求可能由纯 RAG 链路完成，无需伪造 Agent 节点。

## 7. 用量与费用

### 7.1 汇总与归因

顶部显示已知费用、待核价调用数、输入/输出 Token、缓存命中、OCR 页数和调用量。按应用、Agent、知识库构建、在线问答、供应商、模型、日期进行切换。

用量保留供应商原始单位：LLM/Embedding 的 Token、Rerank 的实际计费单位、OCR 页/次、工具 API 次数等，不强行全部换算为 Token。

费用详情记录：能力、供应商、实际模型、请求 ID、用量、单位、单价版本、生效时间、计价币种、折扣/缓存规则、金额、费用来源、所属运行与尝试次数。

### 7.2 计费口径

- 供应商返回金额标记“供应商实报”；根据定价表计算标记“估算”；账单导入核对后才标记“已核对”。
- 不能确定金额时展示“待核价/未知”，不能填 0；无 usage 不自动等同于无消耗。
- 当前阶段不承诺 OpenRouter、AIHubMix、通义百炼均能返回完整 usage 或金额；后续接入按真实响应适配。
- 缓存读写、推理 Token 等可能是输入/输出 Token 的子项；保留供应商口径，避免在总数中重复相加。
- 只对实际计费调用累加；Agent/Skill/对话父节点只是聚合视图，不能再计一次账。
- 每次重试保留独立 attempt 与供应商请求 ID；失败调用也可能产生费用。
- 同一调用的重复上报根据稳定 ID 去重；上下文压缩、索引增强等附加模型调用也需要归因。
- 保留原币金额；汇总币种转换时显示汇率及日期，避免将人民币与美元直接相加。
- 多知识库共同召回的问答费用默认归属应用/本次请求，标记关联的知识库；不把整笔费用各计入每个知识库。分摊策略后续单独定义。
- 定价以调用发生时的版本为准，调整当前价格不静默修改历史费用。

原型提供费用拆分、定价配置抽屉与 CSV 导出示意。预算阈值仅产生预警；自动停用 Agent、扣费、充值与硬限额执行不作为观测页默认功能。

## 8. 总览与异常中心

总览采用指标卡 + 趋势 + 异常/高消耗排行。成功率、错误率、P50/P95 的统计范围和分母可查看；运行中、取消、未知单独计数。只采集部分样本时提示采样口径。

异常列表按错误指纹聚合，展示首次/最近发生、次数、影响应用/文件/运行数、严重度、处理状态、最近一条完整证据。

处理状态为待处理、排查中、已解决、忽略；它不改变原运行的失败状态。支持打开关联运行、添加处理备注、设置站内阈值预警。外部通知渠道和自动修复留到后续。

首版规则示例：任务无心跳、错误率超过阈值、P95 耗时过高、Token/费用预算接近上限、同类工具失败连续出现、OCR 额度不足、待核价数据增长。阈值可配置，不把演示阈值当生产默认值。

## 9. 角色、内容采集与保留

| 角色 | 建议可见内容 |
| --- | --- |
| 管理员 | 全部页面、执行详情、费用与观测设置 |
| 知识库管理人员 | 所管理知识库的构建详情、相关检索与费用汇总；跨应用对话正文不默认开放 |
| 使用者 | 自己会话中的回答、引用与反馈；全局观测入口不展示 |

当前无需登录，角色选择只作为原型视图；上述是未来真实权限的设计，不能据此宣称已实现隔离。“自己会话”在原型只能使用演示/当前浏览器会话维度。

采集模式设计为仅指标、脱敏内容、完整内容三档。企业默认建议脱敏内容；API Key、Authorization、Cookie 等凭据不进入可查看或导出的上下文。正文过长分段展开，显示截断信息和原始大小。

沿用原方案 90 天日志保留建议，正文、原始附件与聚合统计可分别设置；过期内容保留“已过期”说明。具体存储成本需结合调用量、每次上下文体积与保留期评估，不在此虚报容量。

## 10. 数据关联与实现边界

建议在产品层统一以下标识：会话 ID、业务运行 ID、Trace ID、Span ID/父 Span ID、工具调用 ID、构建批次 ID、文件 ID、索引版本、重试 attempt、供应商请求 ID。

一次对话轮次通常对应一个入口 Trace；一个长期 Agent 任务允许因暂停/恢复产生多个关联 Trace，由业务运行 ID 和恢复关系连接。异步构建通过批次/文件/阶段关联；并行耗时不通过子节点耗时简单相加。

事件与费用分开存储：开始/更新/终止事件重建执行过程；usage 记录绑定实际模型或外部调用。原始 usage、归一化 usage 与定价快照并存，方便核对。

LangChain 回调可作为模型、检索、工具事件的接入点；Skill、Harness、队列、worker 和恢复事件需要运行时自行上报。仅有模型回调无法得到完整 Agent 观测。

后续实现建议采用兼容 OpenTelemetry 的关联标识和适配层，观测数据存放于已选的内部环境；Langfuse/LangSmith 可作为对照或后续集成选择，不在本轮引入部署依赖。GenAI 语义规范存在演进，适配时固定版本并显式映射自定义 Skill/Harness 事件。

## 11. 原型演示与验收

首版做全链路可点击演示，覆盖以下场景，所有数值使用同一套关联样例计算：

1. 一批文档部分成功，扫描页 OCR 失败，可从批次下钻到失败文件、页和调用。
2. Agent 成功：加载 Skill → 模型请求 → 检索工具 → Rerank → 最终回答；各级 Token 和费用汇总一致。
3. 工具调用失败后重试恢复，运行最终成功但保留错误和重试费用。
4. Skill 加载成功但后续执行失败，不能显示 Skill 已完成。
5. 工具返回过大导致上下文超限，查看上下文组成、异常节点与终止原因。
6. 超过最大轮数或无心跳，区分明确终止与未知状态。
7. 对话空召回拒答与正常引用，能从会话跳到对应请求链路。
8. usage 缺失、费用待核价、缓存子项和多币种，避免未知当零与重复累计。

交互验收：共享筛选有效；树/瀑布选中联动；输入输出切换与搜索有效；上下文比较可读；费用明细可追溯到调用；异常能定位节点；返回保留筛选；演示与真实数据明确区分。

本阶段实现只添加原型页面、演示数据与交互，并同步到 43123 端口实际运行的预览目录，直接在用户可见页面核对。暂不接入真实采集、供应商账单、Agent 执行、自动重试或告警通知。列表上的“排查/查看”是观测操作，重新执行和取消任务需要未来执行端提供可靠语义后另行接入。

## 12. 参考依据

以下用于验证产品概念；以上页面划分、Skill/Harness 事件和原型交互是知汇台的设计建议，并非声称现有产品已提供全部相同能力。

- [LangSmith：Observability concepts](https://docs.langchain.com/langsmith/observability-concepts)：用 runs、traces、threads 组织单次执行与多轮会话。
- [Langfuse：Observation Types](https://langfuse.com/docs/observability/features/observation-types)：将模型、Agent、工具、检索等作为不同类型的观测节点。
- [Langfuse：Token & Cost Tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking)：区分上报用量/费用与根据模型定价推算的费用。
- [OpenTelemetry：GenAI attributes](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/)：用量、模型、工具与上下文字段的语义参考，缓存及推理 Token 需留意包含关系。
